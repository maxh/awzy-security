# 0090. Relay's output is generated, not committed

- Status: Accepted
- Date: 2026-10-11
- Amends: [0088](0088-the-client-portal-runs-only-its-own-queries.md) (where the backends get the
  persisted queries)

## Context

Each frontend committed the Relay compiler's artifacts (`src/__generated__/`) and, since 0088,
`persisted_queries.json`. They're derived entirely from the frontend's queries and its
`schema.graphql`, `pnpm relay` rebuilds them in under a second without Bazel, and nobody reviews
them. They conflicted on nearly every rebase of a pull request that touched a query, and the
`fix-prs` workflow's commits existed mostly to keep them current.

`schema.graphql` is different: it's printed from the Rust backend, so regenerating it means
compiling the portal, and it's the API contract a reviewer reads.

## Decision

- **Relay's output isn't committed.** `__generated__/` and `persisted_queries.json` are ignored.
  `pnpm relay` generates them from nothing, since the compiler only adds to
  `persisted_queries.json` and persists only the artifacts it writes; `pnpm dev`, `pnpm build`,
  and `pnpm lint` run it first. Each frontend's Bazel `relay` target generates them for the
  typecheck and the Vite build. `fix-prs` no longer regenerates them.
- **`schema.graphql` stays committed**, regenerated by `fix-prs` and checked by `bazel test`, so
  frontend work and `pnpm relay` need no Bazel.
- **The persisted queries ship with the built frontend.** Vite copies `persisted_queries.json` into
  `dist/`, and each backend loads it at startup from the frontend it serves
  (`AWZY_PORTAL_STATIC_DIR`), instead of embedding a committed copy. The frontend and the queries
  it sends by ID can't come apart. A client portal told to run only persisted queries refuses to
  start without a built frontend.
- **The Vite dev server's frontend sends query text.** Relay keeps the text in the artifacts
  (`include_query_text`), and the frontend sends it in dev mode, since a backend run locally, or
  awzy's staging install under 0024, has no map for queries that only exist on a developer's
  machine. A built frontend sends IDs.

## Consequences

- A pull request's diff shows the queries it changes, not their artifacts, and two pull requests
  touching queries no longer conflict over generated files.
- After pulling, a developer runs `pnpm relay` (or `pnpm dev`) before their editor has the types.
- The built frontend serves `persisted_queries.json` like any other file. It holds the same query
  text its JavaScript does.
